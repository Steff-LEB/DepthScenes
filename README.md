# Depth Scenes 1.16

**Download:** [`release/DepthScenes-1.16.apk`](release/DepthScenes-1.16.apk) — debug-signed build for Android 14+ (built for a Pixel 9 Pro XL). Needs [Shizuku](https://shizuku.rikka.app/) and the app's accessibility service.


A standalone no-root Pixel 9 Pro XL test build for the Android 17 QPR3 layout captured on this phone. The selected photo is installed as a static lock wallpaper. A small, touch-through accessibility surface displays its precut subject over the real system clock. Each of the ten scenes has a background-only wallpaper and a lossless WebP cutout of its subject. There is no gallery, cloud inference, network permission, replacement clock, or model download.

## On the phone

1. Start Shizuku with wireless debugging if it is stopped. Switch off the old Pixel Depth or Luma Gallery depth accessibility service.
2. Open Depth Scenes. Tap **Connect Shizuku** and allow the request. In **Open clock layer settings**, enable **Depth Scenes clock layer**. For sideloads where Android disables that toggle, use the app's information page and its **Allow restricted settings** option if available.
3. For a direct comparison with the screenshots, choose **Temple roof**. Tap **Apply to lock screen**. Set a large native clock for the previewed composition.
4. Wake the phone and pause while the clock is visible. Check the clock both before authentication and, if your phone waits for a swipe, after the open padlock appears. Swipe to PIN, return to the lock screen, open notifications, and unlock with the fingerprint reader. Check that the subject disappears during each transition. If a credential or notification is covered, turn the clock layer off in Accessibility. The static wallpaper remains usable.
5. If the edge looks doubled or the upper subject is darker, open **Adjust cutout alignment**. **Cutout scale** moves in 0.5% steps, **Vertical position** moves the cutout up or down in steps of 0.1% of the screen height, and **Cutout brightness** sets the tone. Use the − and + buttons for single steps, tap **Save**, then lock the phone to compare. **Reset** restores 110%, centered, 80%. The starting values of 110% and 80% come from alignment and brightness measurements on the four user screenshots and may need adjustment for this build or device settings.

## Look

The app uses Pixel's Material You styling: colours come from the phone's dynamic wallpaper palette and follow dark and light mode, text uses Google Sans where available, and dialogs and sliders use the DeviceDefault theme. Buttons are pills that morph to rounded squares and shrink slightly when pressed, then spring back with a small overshoot and a haptic tick. Scene thumbnails morph from rounded to squarer with an accent ring when selected, and the preview crossfades between scenes.

## Two images per scene

Each scene now uses two images. `<scene>-plate.jpg` is the background with the building removed, and it becomes the lock wallpaper. `<scene>-front.webp` is the building alone on a transparent background, and the clock layer draws it over the system clock. A small misalignment shows a thin gap at the building's edge instead of a doubled roof, and there is no seam at the bottom of the clock area. Notification cards on the lock screen are cut out of the building with rounded corners, so they appear on top of it and stay readable; the cut-outs follow the cards on every check. When the layer is hidden (PIN entry, the shade, gestures, unlocking), the lock screen shows only the background. The building layer covers the date, padlock and shortcut icons; they stay touchable. `tools/make_plates.py <assets/scenes> [scene]` regenerates the backgrounds from each photo and its cutout. `tools/cut_subject.py <photo> <out.png>` is the texture-seeded GrabCut used to cut the Bonsai scene; its subject rectangle is specific to that photo. `tools/refine_matte.py <photo> <cut.png> <out.png> <canopy_bottom_y>` then mattes the canopy leaf by leaf: it models the smooth backdrop (including the glow seen through gaps), ramps alpha with each pixel's colour distance from it so gaps between leaves become transparent, keeps the trunk and rock solid, and removes backdrop colour from edge pixels. `tools/backdrop.py <photo> <old_cut> <new_cut> <assets> <key>` builds a clean backdrop when the cutout comes from a different render than the photo, as for Bonsai.

In **Adjust cutout alignment**, **Wallpaper scale** (100–160%) and **Wallpaper position** (up to 30% of the screen height up or down) move the background and the building together. Both are saved per scene and re-apply the wallpaper when that scene is on the lock screen. **Cutout scale** and **Cutout brightness** change only the building.

Each scene starts lower on the screen so its subject covers at most 25% of the large clock: Temple roof +2.5%, Airplane wing +8.5%, Tower in clouds +1.0%, Desert mountain +13.0%, Colosseum +10.5% of the screen height. Bonsai uses a separately supplied cutout over a plain backdrop, so its subject moves and scales on its own (Subject size 50–160%, Subject position) while the backdrop stays fixed; it starts at 80% size and 12.5% lower, covering 23% of the clock with the whole tree and rock on screen. Mount Fuji, Between buildings and Amber ridge already cover less than 25%. Flatiron runs through the clock, so no move brings it under 25%; it stays centered. `tools/fit_defaults.py <assets/scenes> <out.json>` recomputes these values.

## Visibility and rendering

Through Shizuku the app requests the default display's current SysUiState and the window manager's visible lock-screen evidence concurrently. Android can report an expanded notification panel while the ordinary lock clock is visible. When that flag is set, Depth Scenes requires the scene container to report an interactive, visible Lockscreen with zero overlays and confirmation that the user has not entered the device. PIN entry, an open shade, or incomplete scene details block that path. An awake, visible keyguard may draw with different wallpaper, IME-focus, or overlay-hiding flags. A secure shade, an explicit PIN screen, or conflicting state suppresses the cutout. Before authentication, the fingerprint window must also be visible. After authentication, Pixel can remove the fingerprint window while waiting for a swipe. This path requires the scene dump to confirm the device is authenticated but has not been entered, a matching Android credential state, and the same visible, nonsecure System UI window. When Android omits the named SysUiState section, the previously verified window profile can confirm the lock screen. Neither query reads credentials. The app discards the system dump and stores only short diagnostic labels and counts.

The selected bitmap is drawn once onto a hidden surface with no input window. The app can then reveal that surface after confirmation. A separate check requires an interactive portrait display showing the keyguard, the same applied lock wallpaper ID and an active full-size System UI window. Known credential, shade, keyboard and notification indicators suppress the layer. The surface attaches to the confirmed System UI window. The large-clock band covers both rows up to 58% of the portrait display height. An exposed compact clock can use a smaller crop. The date on the captured layout begins below this band. Clock alignment may differ with Pixel clock styles. After confirmation the building fades in from transparent to full opacity over 450 ms while rising 6% of the screen height into place, with an ease-out curve. When notifications are on screen it only fades, so the cut-outs stay on the cards. Hiding is instant and cancels the animation. The building also shows on the open-padlock lock screen after face or fingerprint authentication. While it is visible, a watchdog checks every frame (16 ms) and hides it as soon as the lock screen starts going away or any app window, such as the home screen during the unlock swipe, appears in the window list. A visible app window also blocks the reveal. A 1 px off-screen accessibility window with FLAG_WATCH_OUTSIDE_TOUCH receives no taps but is told about every finger-down on the display; any touch hides the building at once, before the unlock swipe moves the lock screen, and it may return 800 ms after the last touch if the lock screen is still confirmed. Once visible, the layer stays up while the next sample is in flight for up to 900 ms, provided the accessibility scan still finds a safe System UI. Window-change events caused by the overlay itself or the clock animation no longer restart the fade, and a clock-size change only moves the crop. An expired sample, missing helper or unknown layout leaves the photo by itself.

Window flags and accessibility events are asynchronous. The short validity limit reduces the opportunity for stale drawings; it cannot synchronize the surface atomically with System UI. The normal-lock check can also suppress the effect after reboot, biometric lockout, or a platform update. The APK was signed and the check was exercised with this user's saved normal and PIN window dumps. Live PIN transition timing and the final visual alignment on this Pixel were not measured.

After a lock/unlock cycle, **Clock layer → Last wake** shows the last decision, the number of checks started and superseded, the reason the wake ended, and the most frequent sampled reason when available. If the app requested a reveal, the compositor line includes the first confirmed transaction time after wake and the longest continuous reveal request. A committed transaction can still be behind another surface. Only an on-device visual check establishes that the cutout covered the clock.

## Build

Open this folder in Android Studio with JDK 17 and Android SDK Platform 35. On Windows run `gradlew.bat :app:assembleDebug`. The APK will be at `app/build/outputs/apk/debug/app-debug.apk`. The Gradle build uses the Shizuku API and provider 13.1.5. A local debug build has its own signing identity.

The scene regression tests in `tests/SceneProofTest.java` use synthetic System UI dumps and the same two window captures. The regression test at `tests/WindowProofTest.java` takes UTF-8 normal-lock and PIN `dumpsys window windows` captures as its two arguments. Compile it with `SceneProof.java` and `WindowProof.java` and run `com.ali.depthscenes.WindowProofTest`. Private system dumps are excluded from this project.
